# 冥零的唱歌部署与切换

适用：安装本地 SoulX-Singer、豆包/本地切换、唱歌服务连不上、RTX 50 系列兼容、复用现有冥零音色、生成本机试听。

## 入口与配置来源

- 工作台「照顾她 → 她会做的事 → 唱歌配置」：豆包云端 / SoulX 本地可切换，并分别保留凭据和本地路径。
- 公共配置：`<工作区>\private\feature-settings.json` 的 `sing.backend`（`doubao` / `soulx`）、`root`、`server_url`、`tries`。
- 豆包凭据：`private\volc-app-id.txt`、`private\volc-token.txt`，和豆包日常语音共用。页面密码框留空保留已有密钥，保存后不回显。
- 真正使用的插件：`bots\AstrBot\data\plugins\astrbot_plugin_dafeiyu_sing`。设置走自设定 `plugins` 块，不直接覆盖运行中的插件配置。
- `tools\self-setup.ps1` 会读取这些覆盖，因此重新自设定不该把 `soulx` 改回包里的 `doubao`。

## 本地部署

已有工作区默认用 `<工作区>\bots\SoulXSinger`；用户指定了目录就尊重其选择。检查剩余空间，首次需下载约 2.8 GB 模型和数 GB 的 PyTorch 环境。安装会创建独立 `venv`，不用 AstrBot/Breeze 的环境。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "<工作区>\tools\setup-singing.ps1" -Base "<工作区>" -Action install
# 指定目录时加 -Root "F:\自选目录\SoulXSinger"
```

Skill 的包装入口：`scripts/deploy-singing.ps1 -Base "<工作区>" -Action install`。部署实现统一在工作区 `tools\setup-singing.ps1`，不要复制一份安装逻辑到 Skill。

当前部署针对 Windows + NVIDIA。使用 Python 3.10、PyTorch/torchaudio 2.7.1 的 CUDA 12.8 构建，兼容 RTX 50 系列。不要恢复旧脚本里的 torch 2.5.1/cu124。结束前会实际运行 CUDA 张量运算并导入模型代码；只安装完成或只看 `cuda.is_available()` 不足以证明能推理。

可重复部署：已存在的虚拟环境和完整模型会保留，未完成的模型下载保留 `.part` 并续传；用户自己的 `voice\prompt.wav` / `prompt.json` 不覆盖。源码版本以本机部署目录的 Git commit 为准，升级前先记录。模型来自 Soul-AILab/SoulX-Singer 官方仓库，hf-mirror 仅用作下载镜像。

## 启动和验收

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "<工作区>\tools\setup-singing.ps1" -Base "<工作区>" -Action start
powershell -NoProfile -ExecutionPolicy Bypass -File "<工作区>\tools\setup-singing.ps1" -Base "<工作区>" -Action check
powershell -NoProfile -ExecutionPolicy Bypass -File "<工作区>\tools\setup-singing.ps1" -Base "<工作区>" -Action test
```

先看 `http://127.0.0.1:18620/health`，要求 `ok=true` 且 `backends` 包含 `soulx`；再生成一次试听，确认真实 WAV 存在、长度合理。`test` 仅生成本机文件，不向 QQ 发消息。需要试听可向用户展示生成的音频。

成功后在工作台选择「SoulX 本地」，保存并启用唱歌。QQ 点歌属于实际发送消息，只在用户要求测试 QQ 发送时执行。

内置曲谱是小星星、两只老虎、生日快乐，歌词可以现编。增加任意歌曲需要曲谱/元数据。

## 用现有冥零声音唱歌

已有的 `mingling` 是保存好的 Breeze 音色，不重新设计或创建音色。在「唱歌配置」中：

- 「使用已有冥零参考」：使用配置包中的 `mingling-参考.wav` 和配套文字。
- 「用已有 Breeze 音色制作唱歌参考」：填写已有音色名（默认 `mingling`）、本机 Breeze 地址（默认 `http://127.0.0.1:8137/v1`）与短句，先用现有音色合成语音，再自动标注并交给 SoulX 唱歌。Breeze 必须已经启动。

这两项都会生成配套的 `voice\prompt.wav`、`prompt.json`、`reference.json`，旧参考先备份。使用 FunASR fa-zh 做真实中文时间对齐、Parselmouth 测音高，再通过 SoulX 数据处理器验证；验证失败不会替换原参考。首次使用需下载约 158 MB 的对齐模型，保持中文短句、清晰人声和 2—30 秒音频。

```powershell
# 直接复用已有冥零参考
scripts/deploy-singing.ps1 -Base "<工作区>" -Action voice_existing
# 或者由已有 Breeze 音色合成短句，再制作参考
scripts/deploy-singing.ps1 -Base "<工作区>" -Action voice_breeze
```

应用后 `/health` 中 `voice_name` 应为「冥零」，再运行 `-Action test` 试听。服务未运行时参考会保存，下次启动生效。Breeze 负责现有音色的语音合成，SoulX 按曲谱生成人声；这项功能不生成伴奏。

## 定位错误

- `logs\singing-progress.json`：界面进度；`logs\singing-install.log`：源码/依赖/模型下载；`logs\singing-server.out.log`、`singing-server.err.log`：模型启动与生成。
- CUDA 失败：先记录显卡、驱动、torch 版本、`get_device_capability()` 和实际 CUDA 运算错误，再调整独立唱歌环境，不要重装整套 AstrBot。
- 端口通但不能唱：检查 `/health` 的 `backends`，不能只凭 18620 在监听报成功。
- 豆包不能唱：先检查 APP ID/Token 是否存在及后台配置；本地检查不调用付费合成。不得自动用云端替代失败的本地请求。
- Windows PowerShell 5.1 会把 git/curl 的 stderr 进度当错误对象；部署脚本按退出码判断成败。
- CUDA 探针使用 `tools/check-singing-env.py` 文件执行，避免 PowerShell 5.1 的 `python -c` 引号导致只打印版本却跳过实际运算。

修改已有 `private` 或 AstrBot 数据前备份；已有服务不为了测试随意结束。本地唱歌会和 Breeze/Ollama 共享 GPU/内存，显存不足时先查进程占用，再协调服务，不清除模型和记忆。
