# 发布这份 skill（工作台「一键更新」靠的就是这个约定）

工作台查新版的顺序（`win32\src\her\her_actions.cpp` 的 `FetchUpdates` / `SkillUpdate`）：

1. 直连、以及几个加速站轮着来：
   `https://github.com/<skill 仓库>/releases/latest/download/skill-version.json`
2. 读到 `version` 就跟 `tools\skill-version.json` 里的比；大就显示「有新版」+「一键更新」。
3. 「一键更新」下的包固定叫 `releases/latest/download/mingling-install.zip`，
   解压后顶层必须是 `mingling-install\`，里面必须有 `SKILL.md`、`version.json`、`scripts\finish.ps1`。
4. 换之前把现有的 skill 目录整份拷到 `<工作区>\旧版\MMdd-HHmm-Skill<旧版本>\`。
5. 换完自动跑一次那个包里的 `scripts\finish.ps1 -Dir <工作区>`，把 `tools\skill-home.txt` 和
   `tools\skill-version.json` 刷新成新版本。

## 发布步骤

```powershell
cd "<工作区>"                       # 仓库根
# 1) 改版本号：skill\mingling-install\version.json 的 version / date / notes
# 2) 打包（顶层目录必须是 mingling-install）
Remove-Item tmp\mingling-install.zip -ErrorAction SilentlyContinue
Compress-Archive -Path skill\mingling-install -DestinationPath tmp\mingling-install.zip -Force
# 3) 发 release：tag 用 skill-v<版本>，两个资产
gh release create skill-v0.2.0 tmp\mingling-install.zip skill\mingling-install\version.json `
  --repo linyuehua0010/mingling-workbench --title "冥零安装 Skill v0.2.0" --notes-file skill\mingling-install\version.json
```

## 注意

- skill 的 release 必须发成 **最新**（非 prerelease、时间最新），否则 `releases/latest` 拿到的还是旧的那条。
  工作台的快照通道用的是 prerelease + tag 里带 `snapshot`，两条通道互不干扰，可以同仓库并存。
  V3.0.0 正式版发布后，快照通道停在 V3-snapshot-3，下一份快照是 V4-snapshot-1（尚未发布）。
- 没发布之前，更新页那行显示「本机 0.2.0」，说明写的是「这一版还没发到 GitHub」——
  这是认真话，不是坏了。发布之后同一行会变成「最新」或「有新版」。
- 本地改了 skill 但还没发版时，别忘了跑一次 `scripts\finish.ps1 -Dir "<工作区>"`，
  否则 `tools\skill-version.json` 还是旧版本号，工作台会以为你装的是老版。
