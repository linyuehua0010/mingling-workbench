# 冥零工作台 v2.2.0 · 使用与配置说明

这一版把「装机器人」从一堆手工步骤收进了窗口里：五个组件一键装、人设一键导、求助页的字能改、掉线会用人话叫你。

> 只讲怎么用和怎么配。为什么这么改，见 [CHANGES.md](CHANGES.md)；验收记录见 [ACCEPTANCE.md](ACCEPTANCE.md)。

---

## 1. 装完之后先做一件事：把「机器人根」指对

工作台里有两套目录，很多人第一次会被这里绊住：

| 概念 | 默认 | 装什么 |
|------|------|--------|
| 工作区（workspace） | `文档\冥零工作台` | 看 B 站的产物 `out\`、临时 `tmp\`、日志 `logs\`、台账 |
| 机器人根（base） | 工作区的上一级 | AstrBot、SnowLuma、Breeze、Ollama 这些组件的安装位置 |
| 组件根（bots） | `<工作区>\bots` | **v2.2.0 起推荐**：五个组件统一装这里 |

已经有一台跑着的机器人（比如 `D:\`），就把 `base` 指过去，否则维护页会全红——检测是在 `<base>\bots\` 和老的平铺目录里找的。

**怎么核对**：

```bat
MinglingWorkbench.exe --paths
```

会打出「工作区 / 机器人根 / 组件根 / AstrBot / SnowLuma / Breeze / Ollama」六行绝对路径。对的就往下走，不对就改配置。

**改在哪**：`%APPDATA%\MinglingWorkbench\settings.json`

```json
{
  "workspace": "D:\\MinglingWorkbench",
  "base": "D:\\"
}
```

注意是**双反斜杠**（JSON 转义），或者用正斜杠 `D:/` 也行。

## 2. 一键配置环境（维护页 →「一键自动配置」）

按下之后跑两段，进度条在维护页顶部：

1. **补环境**：Node、ffmpeg、Python、Ollama（检测）、工作区目录、密钥目录；
2. **装组件**：AstrBot、SnowLuma、Breeze、Ollama、bili-whale 依次装到 `<组件根>\<名字>\`。

装完 `<组件根>` 下会多出：

```
bots\
  AstrBot\         start.cmd / env.cmd
  SnowLuma\        node.exe / index.mjs / config\
  Breeze\          start.cmd / models\
  Ollama\          ollama.exe / models\
  bili-whale\      package.json / bin\
  start-all.cmd    一键全起
  .setup.json      这次装了什么、成功/失败，排错先看它
```

**手动跑**（不想开窗口、或想换个目标目录）：

```powershell
powershell -ExecutionPolicy Bypass -File tools\auto-setup.ps1 `
  -Workspace "D:\冥零工作区" -Bots "D:\冥零工作区\bots" -Base "D:\冥零工作区"
# 只想装某几个：-SkipOllama -SkipBreeze
# 全跳过、只检查目录：-Force 别加，直接 -SkipAstrBot -SkipSnowLuma -SkipBreeze -SkipOllama -SkipWhale
```

脚本会写两个**用户级环境变量**：`MINGLING_BOTS`（组件根）和 `OLLAMA_MODELS`（模型目录）。这是为了让下次启动不用再问路径——但 `OLLAMA_MODELS` 指到哪，Ollama 就只认哪的模型，跑之前想清楚 `-Bots` 指哪儿。

命令行也能跑一遍看结果：

```bat
MinglingWorkbench.exe --bots-setup
```

## 3. 冥零的人设（维护页 →「导入冥零人设」）

人设只存在于 **AstrBot** 里（SnowLuma 只管登 QQ，它的配置没有 persona 字段，塞进去下次启动就被覆盖）。

导入器做四件事：

1. 登录 AstrBot 后台，把人设写进 `personas` 表（同 id 更新，没有就新建）；
2. 把 `agent_runner.config.persona.persona_id` 切成新人设（不切不生效）；
3. 白名单条目 `"旧名字:FriendMessage:<qq>"` 的前缀换成新名字；
4. 同一份正文写到 `<Base>\tools\pet-persona-mine.txt`，桌宠共用。

**准备登录**：`<Base>\private\backend.txt` 写两行

```
username: 你的后台账号
password: 你的后台密码
```

不想存密码就换成一行令牌：

```
token: eyJhbGciOi...
```

（令牌可以用后台配置里的 `dashboard.jwt_secret` 自己签：HS256，payload `{"username":"…","exp":…}`。）

**手动跑**：

```powershell
# 模板还是空的，先预览
powershell -ExecutionPolicy Bypass -File tools\import-mingling.ps1 -DryRun

# 已经有一份写好的整篇人设，直接用它
powershell -ExecutionPolicy Bypass -File tools\import-mingling.ps1 `
  -PersonaFile "D:\\dafeiyu-config-pack\persona\大肥鱼.md"
```

`-DryRun` 只在 `<Base>\logs\mingling-persona.filled.md` 落一份成品给你看，不碰后台。

**想改成自己的角色**：填 `plugin\mingling_skill\persona\mingling.md` 里的 `{user_persona}`（她是谁）和 `{user_tone}`（她怎么说话）；或者复制 `mingling-persona.sample.json` 到 `<Base>\private\mingling-persona.json` 再填。

**导入成功但聊天还是旧人设**：重启 AstrBot（维护页「重启大脑」）。

## 4. 求助页的字可以改成你的（求助页 → 每张卡「改文字」）

11 张卡片，每张下面都有「改文字」和「复制这句」：

- 点「改文字」弹一个多行输入框，写你自己的话，**保存**就落盘；**留空**保存 = 恢复默认那句；**取消/点空白** = 不改。
- 「复制这句」复制的是改过之后的正文，粘到 DeepSeek Harness 里发给 Agent 就行。

改的内容存在 `settings.json` 的 `custom_help_texts` 里：

```json
{
  "custom_help_texts": {
    "role": "换我自己的角色：名字叫……，性格是……",
    "voice.title": "换个更温柔的声音"
  }
}
```

键名 = 卡片 id，11 个 id 依次是：

| id | 卡片 |
|----|------|
| `role` | 换成我自己的角色 |
| `voice` | 换个声音 |
| `breeze` | 换成 Breeze 在线版 |
| `dialect` | 听懂更多方言 |
| `group` | 让她进我的 QQ 群 |
| `silent` | 她不回话了 |
| `always` | 电脑关机她也在线 |
| `napcat` | QQ 升级后先换成 NapCat |
| `backup` | 用备份还原 |
| `uninstall` | 卸载她 |
| `memory` | 记忆没接上 |

- 只写 `<id>` = 改正文；
- 写 `<id>.title` = 连标题一起改。

这个键是**对象**，和别的扁平键不一样；工作台对 `settings.json` 是「原文编辑」，不会因为不在白名单就把你手写的键抹掉。

## 5. 帮助页：组件路径与状态从哪来

帮助页正文的「当前路径」一节现在会列出：

```
工作区 / 台账 / 状态 / 组件根 / AstrBot / SnowLuma / Breeze / Ollama
```

按钮区多了「组件目录」，直接打开 `<组件根>`。

**状态检测**（维护页 8 张卡）的顺序是：先 `<组件根>\<名字>\`，再老的平铺目录（`<Base>\astrbot`、`<Base>\SnowLuma`、`<Base>\breeze-tts`、`<Base>\Ollama`）。所以：

- 新装的（bots 布局）和老装的（平铺）都能认；
- 两个地方都装了同一组件时，**bots 下的优先**。

## 6. 掉线提醒（维护页能开，也能自己配文案）

后台常驻一条心跳，默认 **每分钟**看一次 SnowLuma（5099）、AstrBot（6199）、Breeze（8137，只有本机语音在用的时候才盯）：

- 连着两次没起来才算掉线（避免重启瞬间误报）；
- 同一条 10 分钟内只提醒一次；
- 提醒有两个形态：**右上角滑动横幅**（点里面「重启一下」就直接拉起来）和**托盘气泡**（带自定义头像）。Windows 11 上气泡偶尔不弹，所以横幅是主路径。

**改文案**：`settings.json`

```json
{
  "notify_title": "冥零 · 掉线提醒",
  "notify_body": "哎呀，{name} 掉线了，快重启一下大脑吧~",
  "notify_avatar": "D:\\MinglingWorkbench\\art\\avatar.png",
  "notify_every": "60"
}
```

- `{name}` 会被换成组件名，`{time}` 换成时间；
- `notify_every` 单位秒，钳在 30–600；
- `notify_avatar` 留空就用界面里那张头像；
- 想让提醒**彻底闭嘴**：建一个空文件 `<Base>\private\qq-watch-off.txt`。

维护页的 `watch_on / watch_off / 试一条` 走的是同一套开关。

## 7. settings.json 全键表

| 键 | 值 | 说明 |
|----|----|------|
| `workspace` | 路径 | 工作区（产物/日志/台账） |
| `base` | 路径 | 机器人根 |
| `botRoot` | 路径 | 组件根，默认 `<workspace>\bots` |
| `secrets` | 路径 | 密钥目录，默认 `<base>\secrets` |
| `notify_every` | `"60"` | 心跳间隔（秒，30–600） |
| `notify_title` | 文本 | 提醒标题 |
| `notify_body` | 文本 | 提醒正文，支持 `{name}` `{time}` |
| `notify_avatar` | 图片路径 | 气泡/横幅头像 |
| `mirror_node` | URL | Node 下载镜像 |
| `mirror_ffmpeg` | URL | ffmpeg 下载镜像 |
| `custom_help_texts` | 对象 | 求助页改过的卡片文字 |

前三个路径可以写 `F:/...`，读出来会自动归一成反斜杠。

## 8. 常见问题

**维护页全红，但机器人明明在跑**
`base` 没指对。跑 `--paths` 看「机器人根」是不是你的真实安装位置。

**一键配置说装好了，但路径还是老的**
`auto-setup.ps1` 会写用户级 `MINGLING_BOTS`，它**优先于** `settings.json` 的 `botRoot`。用 `--paths` 的「组件根」核对，错了就把那个环境变量删掉重跑，或者启动前先改它。

**导入人设说「后台没登录上」**
`<Base>\private\backend.txt` 不存在或账号不对。写用户名密码，或写一行 `token:`。

**中文变成问号**
导入脚本里已经处理过（发 UTF-8 字节、收原始字节自己解）。自己写 PowerShell 调后台时别用 `Invoke-RestMethod` 直接发字符串 body。

**托盘气泡不弹**
Windows 11 的通知设置里可能关了这个应用的弹窗；横幅不受影响，点「重启一下」一样能修。

**改了求助页文字，想恢复**
再点「改文字」，清空，保存。

## 9. 卸载与回滚

- 卸载只删**程序**（`%LOCALAPPDATA%\Programs\MinglingWorkbench`），不删工作区里的 `out\tmp\logs`，也不删密钥目录。
- 组件根（`bots\`）里的东西是组件自己的，卸载不会动；不想要了就手动删。
- 人设想退回原来那个：AstrBot 后台「人格」页把默认人设切回去，导入工具只新建/更新，不删旧的。
- 导入人设前的备份在 `<Base>\astrbot\data\cmd_config.json.bak-*` 和 `data_v4.db.bak-*`（如果你手动备份过）。
